RESUMEN EJECUTIVO
─────────────────
  Se desarrolló exitosamente un proyecto de automatización QA
  profesional que cubre dos dimensiones críticas de las pruebas
  de software:

  1. Automatización E2E con Cypress para SauceDemo (UI Testing)

  El proyecto demuestra el uso de patrones de diseño modernos,
  buenas prácticas de QA y una estructura escalable lista para
  ambientes productivos.

BENEFICIOS DE LA AUTOMATIZACIÓN E2E
──────────────────────────────────────
  1. DETECCIÓN TEMPRANA: Detecta regresiones en el flujo crítico
     de compra antes de llegar a producción.

  2. EJECUCIÓN RÁPIDA: El flujo completo se valida en ~30 segundos
     vs. 5–10 minutos de prueba manual.

  3. EVIDENCIAS AUTOMÁTICAS: Screenshots y videos de cada ejecución
     sirven como evidencia de calidad para stakeholders.

  4. MANTENIBILIDAD: El patrón POM centraliza los selectores,
     reduciendo el impacto de cambios en la UI a un solo archivo.

  5. CONSISTENCIA: Elimina la variabilidad humana en la ejecución
     de pruebas repetitivas.

ARQUITECTURA TÉCNICA E2E
──────────────────────────
  Se implementó el patrón Page Object Model con las siguientes
  responsabilidades:

  - LoginPage.js    : Encapsula interacciones con el formulario de login
  - InventoryPage.js: Maneja el catálogo de productos y el carrito
  - CartPage.js     : Gestiona la visualización y acciones del carrito
  - CheckoutPage.js : Controla los 3 pasos del proceso de compra

  Los datos de prueba están externalizados en fixtures (JSON),
  permitiendo modificarlos sin tocar el código de los tests.

ESTABILIDAD DE LAS PRUEBAS
────────────────────────────
  La suite es estable porque:
  - No usa sleeps arbitrarios (cy.wait con número)
  - Usa assertions de Cypress que esperan automáticamente
  - Maneja excepciones no capturadas del sitio
  - Los selectores usan data-test attributes cuando están disponibles
  - Las URLs se validan después de cada navegación

CONCLUSIÓN FINAL
────────────────

  CI/CD y escalar hacia una cobertura de pruebas más amplia.
